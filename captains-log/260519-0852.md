# Captain's Log: 260519-0852

## Strategic Pivot: Beyond Bash
We have officially decided to move beyond the shell-based prototype scripts (`scripts/steel/*.sh`) for VM orchestration. While these scripts were invaluable for rapid prototyping and exploring KVM/Firecracker/eBPF primitives, they have reached their scalability limits. 

The complexity of managing concurrent resource allocation (cgroups, IPs, TAPs) and the lack of deep observability into race conditions made continued development in bash a bottleneck.

## Achievements
- **Prototype Finalization:** Committed the final state of the `scripts/steel` prototypes as a baseline.
- **Observability Stack Integration:** Fully integrated OpenTelemetry (OTLP/gRPC) into the Rust control plane.
- **Dogfooding Infrastructure:** Established the "System VM" pattern (ADR 008) where critical infrastructure like the OTel Collector and Jaeger run inside Firecracker microVMs managed by the Microvisor.
- **Static IPAM:** Implemented a dual dynamic/static IP allocation strategy in Rust to support deterministic system service locations.

## Technical Decisions
- **Full Rust Lifecycle:** All future VM management (provisioning, networking, cgroups, launch) will be implemented natively in the Rust control plane.
- **OTEL-First Debugging:** The Rust orchestrator will rely on Jaeger-based waterfall charts to diagnose lifecycle latency and kernel-level errors.

## Pending Tasks
- **Rust Provisioning Implementation:** Implement the actual `ioctl` boundaries in `src/vmm/storage.rs` and `src/vmm/network.rs` to remove mocks.
- **System VM Auto-Boot:** Logic in `main.rs` to boot the Telemetry VM and wait for the OTLP endpoint to become healthy.
