# Captain's Log — 2026-05-19 23:24

## Session Summary

Short session to close the two pre-Spec-006 blockers identified in the cross-review. Both fixes committed together as `fix(control-plane): close eBPF fail-open and thin-pool ID leak`.

## Achievements

### Fix #3 — eBPF fail-open → fail-closed
Changed both `tc_egress` and `tc_ingress` error handlers from `TC_ACT_PIPE` to `TC_ACT_SHOT` in `microvisor-ebpf/src/main.rs`. A malformed or truncated packet that cannot be fully parsed now drops rather than forwarding. The old behaviour was a security bypass vector: a crafted short packet could skip the anti-spoof guard and SSRF block entirely.

### Fix #5 — DM thin-pool ID leak
`StorageManager::delete_snapshot` previously only called `dmsetup remove` (removes the device node) but never issued `dmsetup message <pool> 0 delete <id>` (releases the thin-pool's internal metadata slot). Every VM teardown leaked one slot permanently, eventually exhausting the 24-bit ID space.

Changes to wire this through:
- `create_snapshot` return type changed `io::Result<PathBuf>` → `io::Result<(PathBuf, u32)>`; returns the snapshot's internal ID alongside the device path
- `delete_snapshot` gains `snapshot_internal_id: u32` parameter and issues the two-step cleanup
- `ProvisioningContext` gains `snapshot_internal_id: Option<u32>` field; `cleanup()` pairs it with `snapshot_name` via `if let (Some(name), Some(id)) = (...)` so neither can be called without the other

Also fixed an introduced warning: changed `spawn_blocking(...).await?;` (discarded inner `Result`) to `let device_path = spawn_blocking(...).await??;` with double `?` and used the returned `PathBuf` directly.
