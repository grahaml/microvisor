## What we built

### Build pipeline (`make`)
- `make all` / `make check` / `make run` for full setup and launch
- `make cgroup` — creates `/sys/fs/cgroup/orchestrator` and enables cpuset+memory
  controllers; idempotent, prompts for sudo once
- `make pool` — DM thin pool setup (already existed, fixed a disk-filling dd bug
  in a prior session)
- Binary build/run separation: `cargo build` as the user, `sudo <binary>` to run —
  avoids the sudo+cargo PATH problem entirely

### First-boot bug fixes (all in `control-plane/`)
| Issue | Root cause | Fix |
|---|---|---|
| `PermissionDenied` on cgroup | `cgroup.subtree_control` empty | `make cgroup` writes `+cpuset +memory +pids` |
| `EINVAL` writing PID to `cgroup.procs` | Jailer owns its own cgroupv2 subtree; we can't move a process across subtree boundaries | Pass constraints via `--cgroup` flags to jailer; remove `add_process` call |
| Jailer crashes immediately | Relative paths (`./bin/firecracker`) rejected; missing `--cgroup-version 2` on pure cgroupv2 host | `canonicalize()` at init; add `--cgroup-version 2` flag |
| `PermissionDenied` on `/dev/rootfs` | `mknod` creates device owned by root; Firecracker runs as UID 1000 | `chown` device node to `jailer_uid:jailer_gid` after mknod |
| `PermissionDenied` on `/metadata.ext4` | Same as above | `chown` metadata image after creation |
| `EBUSY` on TAP attach | Orchestrator held TAP fd open; Firecracker's `TUNSETIFF` failed | `TUNSETPERSIST 1` then close fd; implement Drop to un-persist on teardown |

### ADR-009 update
Documented the jailer UID/GID risk: chown'ing chroot files to a real host user
means a chroot escape would execute as that user. Upgrade trigger documented:
dedicated system account (UID ≥ 10000, no shell, no home) before any non-team
deployment.
