# Captain's Log: 260521-1430

## Achievements

### fs-storage (Layer Store)
- Implemented the full `fs-storage` crate in Rust — a content-addressed layer store for Microvisor rootfs artifacts.
- Core data structures: `ContentHash`, `InputHash`, `LayerMeta`, `ReleaseManifest`.
- `StorageBackend` trait with two backends:
    - `LocalJsonBackend`: Atomic filesystem-based storage with content-addressed layout.
    - `InMemoryBackend`: Fast, lock-backed storage for unit/integration testing.
- `LayerStore` high-level API: dual-format layer publishing (`ext4.zst` + `oci.tar.zst`), inline checksumming via `HashingReader`, manifest management, build catalog queries, mutable tag pointers, mark-and-sweep GC, and offline integrity verification.
- gRPC API via Tonic with multiplexed streaming for concurrent artifact ingestion.
- All 7 integration tests passing.

### build-system (Steel Pipeline)
- Implemented the full `build-system` crate — Dockerfile-to-ext4 build pipeline.
- Dockerfile parser that extracts `steel.*` labels into a build DAG with layer ordering and release metadata.
- BuildKit integration: drives `buildctl` stage-by-stage with parent cache injection for cache-hit stages.
- Layer conversion: `mke2fs` → ext4, `tar` → OCI, `zstd -19` compression for both artifacts.
- Content addressing: input-hash (stage definition + parent) for cache lookup, output-hash (SHA-256 of raw ext4) for blob identity.
- gRPC store client: publishes layers and release manifests to fs-storage.
- CLI via clap: `steel-build build --file <Dockerfile>`.

## Technical Decisions
- **Tonic (gRPC)**: Remote API layer for its safety, performance, and first-class streaming in the Tokio ecosystem.
- **Multiplexed Ingestion**: `oneof` payload in a single gRPC stream to ingest deploy + cache artifacts concurrently without disk/memory buffering on the server.
- **Protobuf-Compiler**: System `protobuf-compiler` via `apt` for fast build times vs. compiling `protoc` from source.
- **Proto Divergence (Known)**: The shared `proto/fs_storage.proto` and `fs-storage/proto/fs_storage.proto` have drifted — field names and `ListBuildsRequest` structure differ. Wire-compatible for the build flow but needs reconciliation before adding more RPC callers.
- **Tonic Version Skew (Known)**: build-system uses tonic 0.10/prost 0.12; fs-storage uses tonic 0.12/prost 0.13. Works today but should be unified.
