# Captain's Log: 260519-1228

## SME Review & Context-Doc Hardening

Brought in an SME consultant to thoroughly review the documentation set before the first Rust orchestrator commit. The goal was a context-package quality check — the docs are upstream of every future agent task, and contradictions or hallucinations in them compound.

The review surfaced six outright technical errors, ten significant gaps, and a structural bias problem (five of eight ADRs were observability-focused; zero covered security boundaries, storage, or networking). Output captured in `docs/003-expert-review.md` with severity tiers (🔴 blocker / 🟠 significant / 🟡 imprecise / 💡 opportunity).

## Achievements

### Hard errors fixed in-spec
- **Spec-008**: rewrote the dm-thin ioctl sequence with the missing `DM_TARGET_MSG → create_snap` step and `DM_SUSPEND_FLAG` semantics; replaced loop-mount metadata-drive provisioning with `mke2fs -d`.
- **Constraint-006**: dropped obsolete `entropy_avail > 3000` check (post-Linux-5.18 RNG overhaul made it meaningless); replaced with `crng init done` dmesg signal.
- **TAD / PRD / Constraint-007**: tightened "microsecond boot" / "nanosecond latency" hyperbole to defensible target numbers (p99 cold boot < 200 ms; KVM_RUN re-entry < 5 µs; eBPF NAT < 200 ns/64B); fixed `O_DIRECT` vs `io_uring` conflation.
- **TAD §1.1**: added `irqaffinity=` and `kthread_cpus=` to the kernel cmdline example (without them, isolated cores still get IRQ traffic); noted `cpuset.cpus.partition=root` as the modern equivalent.
- **Spec-006**: added SMT host-policy callout alongside `smt: false` — the Firecracker flag only controls what the guest sees, not whether the host co-schedules SMT siblings across tenants.
- **Spec-007**: added pseudo-header L4 checksum handling (`BPF_F_PSEUDO_HDR`), ICMP + inner-IP rewrite for PMTUD, explicit drop rule for `169.254.169.254/32` (cloud-metadata SSRF), MTU sizing notes.
- **Spec-003**: explicit single-NUMA branch — orchestrator must read `/sys/devices/system/node/` at startup and treat `num_nodes == 1` as a first-class case (matters for the macbuntu POC host *and* most single-socket production servers).
- **Spec-005**: mandated `spawn_blocking`/`block_in_place` wrappers around known-blocking syscalls; kept the 1 ms threshold as a guardrail metric, not the primary defense.

### Four new ADRs locked in
- **ADR 009** — Multi-tenancy threat model. Single-tenant POC; `jailer` mandatory from day 1; default Firecracker seccomp preserved; cpuset allocator built as a trait so sibling-aware pinning is a drop-in upgrade (not a refactor); explicit multi-tenant trigger reopens the SMT decision.
- **ADR 010** — Storage architecture. dm-thin v1 with the corrected ioctl sequence; `error_if_no_space=y` for POC pool-exhaustion (loud failure preferred over silent hang); named v2 migration triggers (density > 50 VMs → sharded pools, then SPDK); auto-extend tier explicitly deferred.
- **ADR 011** — Network model. Per-VM TAP + eBPF stateless 1:1 NAT as v1; alternatives (host bridge, macvtap, vhost-user-net) compared and rejected; host-routable IP range becomes configuration (not hardcoded 10.0.0.X); guest link stays on 169.254.1.2 for v1 with CGNAT migration deferred; `vhost-net` named as v2 substrate trigger.
- **ADR 012** — Crash-recovery contract. All four components accepted, sequenced: Phase A in first commit (`PR_SET_PDEATHSIG, SIGKILL` + idempotent per-state `cleanup()`); Phase B before in-place restart is allowed (adoption scan); Phase C post-POC (reconciliation loop).

## Technical Decisions

- **dm-thin stays as v1 storage substrate** — the SME review's storage critiques were about the in-spec ioctl sequence (now fixed) and pool-exhaustion policy (now explicit), not about dm-thin itself. v2 migration to sharded pools or SPDK has named triggers in ADR 010.
- **`jailer` is mandatory from day 1** — retrofitting it after the orchestrator manages bare Firecracker processes is significantly more painful than building on top of it. Anchors the per-VM on-disk layout (`/srv/jailer/firecracker/<vm-id>/`) that the adoption scan in ADR 012 Phase B will rely on.
- **Cpuset allocator behind a `trait`** — POC ships with a naive SMT-blind implementation; multi-tenancy gets a sibling-aware allocator as a config-only swap. No state-machine, cgroup-writer, or request-validation changes required.
- **Loud failure preferred for POC** — `error_if_no_space=y` on the thin pool (returns EIO instead of silent hang); single-tier vs the production two-tier (`dmeventd` auto-extend + fallback) policy.
