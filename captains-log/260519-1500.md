## Technical Decisions

- **Deployment model**: Orchestrator loads BPF per-VM at `ConfiguringNetwork` state — no separate daemon needed. `EbpfProgram` lifetime tied to `VmHandle`, so teardown is automatic.
- **Byte order discipline**: IPAM returns host-order `u32`; stored in `VmConfig` as network order (`.to_be()`); BPF constants use `u32::from_be()` to match what `ctx.load::<u32>()` returns on `bpfel` target.
- **Nightly toolchain risk**: Contained to `microvisor-ebpf` only (stable control-plane unaffected). Pinned date prevents silent breakage; upgrade procedure documented in Spec-007.
