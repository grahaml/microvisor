# Captain's Log: 260518-1530

## Achievements
- **Observable State Machine:** Refactored the VM launch path from a linear sequence to an event-driven state machine (`VmStateMachine`).
- **Unified Observability:** Integrated `tracing` with structured JSON output. Every VM session is now correlated with a unique 64-bit `session_id`.
- **Syscall Auditing:** Implemented a `SyscallAuditor` to detect and warn about blocking operations exceeding 1ms, protecting the `tokio` runtime from starvation.
- **Rich Error Handling:** Introduced `OrchestratorError` which captures the `session_id` and the state at failure for precise debugging.
- **Infrastructure:** Added `tracing`, `tracing-subscriber`, and `rand` dependencies to the control plane.

## Technical Decisions
- **Reserved Keywords:** Transitioned from `rand::rng().gen()` to `rand::rng().random()` to align with Rust 2024 reserved keyword `gen`.
- **State Transitions:** Enforced a strict lifecycle: `Pending -> ProvisioningStorage -> ConfiguringNetwork -> InitializingCgroup -> LaunchingVMM -> Running`. Allowed emergency transitions to `Terminating` from intermediate states.
- **Non-Blocking Guarantee:** Any filesystem write to cgroups is now audited for latency.

## Pending Tasks
- **Emergency Teardown Implementation:** Implement the actual cleanup logic in the `Terminating` and `Destroyed` states.
- **Actual eBPF Mapping:** Replace the `link_cgroup_to_session` stub with real BPF map updates using `libbpf-rs` or similar.
- **Firecracker Integration:** Map the `VmStateMachine` states to actual Firecracker API calls (e.g., `PUT /machine-config`).
